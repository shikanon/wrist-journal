# 恩名手记 · WristJournal

恩赐于此名的手机 App，用于记录你的上下文（context）。

用 Apple Watch 录下日常、想法和工作记录，可选择附上录音开始时的大致地点。录音可在 Watch 或 iPhone 调用火山方舟整理，也可导出到 Mac 自行处理。iPhone「报告」首页可直接切换日报、周报、月报，日报支持图文编辑。录音明细在独立标签；原音可选择备份到私人 iCloud。

## 使用

1. 在手表首页点「开始录音」。数码表冠保留系统导航和滚动用途，不再触发录音。录音真正启动后给出触觉反馈，默认立即进入黑底防误触界面；长按 1.5 秒解锁，可「标记此刻」或「停止并保存」。控制面板 5 秒无操作自动锁定，放下手腕或离开应用也会锁定。VoiceOver 提供独立解锁按钮。系统中断尽量保存可播放部分，结果提示重启后仍可见。黑底界面不等于强制物理熄屏，熄屏由 watchOS 控制。详见[Watch 录音体验与验收](docs/Watch录音体验与验收.md)。
2. 在手表「录音与健康 → 录音设置」可开启「记录录音地点」。每段录音记录当时时区，并在开始时获取一次粗略位置；15 秒无结果、停止录音或关闭设置都会取消定位。
3. 在 iPhone 设置选择「优先手表」「优先手机」「优先云端」，默认优先手表。手表模式等待手机定期拉取结束日期；手机模式默认每 60 分钟批量发送，确认入库后释放手表副本；云端模式确认私人 iCloud 保存后释放手表原音，再由手机读取分析。设置对后续录音生效，实际后台时机由系统决定。手机「录音」页可主动同步、回听和导出。
4. 在 iPhone 设置选择「数据处理」，默认手机处理，与存储位置独立。手机或 Watch 模式使用「进阶设置」配置的方舟 Key。手动分析前可查看日期、录音段数和清理条件，也可开启「自动每日分析」。Watch 首次获取 Key 需两端可达，结果回传手机归档。「不处理」停止模型和日报清理，并将「Mac 临时下载」放在处理选项下方。自动任务默认充电、非低电量且未过热时运行，并限制上传网络。详见[数据处理模式](docs/数据处理模式.md)。
5. 在 iPhone「健康」开启健康读取，也可在进阶设置管理开关。默认使用系统采样；可选择「精准模式」，在录音期间以约 10 Hz 主动采集手腕运动并监听新增心率，结束即停止。**心率采样频率仍由 watchOS 控制**，精准模式不启动训练，也不保证连续心率。
6. 在「报告」首页选日报、周报或月报。日期栏从左到右显示前五期和当前一期，有报告的日期下有圆点；「选日期」可打开更早的报告。日报首屏直接展示当天的记录，单条长录音也可整理出多个话题；今天未归档时，优先打开最近六天里有可读内容的日报。「录音与来源」可核对录音整理全文、地点、原文引用与时间标记。周报按周一至周日、月报按自然月展示已有日报的摘录和入口。
7. Mac 下载：手机设置 →「Mac 临时下载」，先同步录音，再开启。可逐段下载原音及包含 UTC 时间、时区、地点、运动窗口和已有报告的 JSON 元数据。两台设备连接同一 Wi-Fi，Mac 打开完整 HTTPS 网址，核对证书 SHA-256 指纹。默认 10 分钟无有效操作关闭，可设 1–60 分钟；手机进入后台、Wi-Fi 变化或手动关闭也会停止。

watchOS 普通应用不支持此类局域网网页监听，因此 **Mac 下载需要 iPhone 中转**。手表云端上传使用 CloudKit 并禁止蜂窝请求，但 Apple 决定使用配对手机代理还是手表网络，无法强制直连手表自身 Wi-Fi。脱离手机时需已知可用的 Wi-Fi。详见[存储模式与连接限制](docs/存储模式与本地下载.md)。

## 编辑日报

点日报标题旁的编辑图标，可以修改标题和正文，也可添加最多三张照片及说明。正文支持 `## 小标题`、`- 列表` 和 `**加粗**`，保存前可切换「预览」。恢复自动正文不会移除照片。编辑版单独保存在本机；新录音及健康数据更新时会保留手动正文，原整理文字与引用仍可查阅。「分享日报文字」只分享标题和正文。

手机处理模式下，有可读录音内容的日报可在编辑器中选择「用 AI 整理当日记录」，一条录音也可以起草。确认后向火山方舟发送最多 12 条已有整理文字，可能包含此前附加的心率汇总；不会发送照片、原音或编辑内容。生成的草稿可以继续修改，保存后才替换正文。Watch 处理模式在手机端用已有整理文字生成正文，无需额外调用模型。

## 原始数据与备份

- 手表录制 16 kHz、32 kbps、单声道 AAC，约 14.4 MB/小时，不开启实时音量计。定位不是连续追踪。
- 手机／Watch 处理模式默认在日报原子保存后删除两端应用内原音，保留摘要、原文引用、时间标记、地点及清理标记。设置中可开启「日报后保留原音」以支持回听；再次关闭后，下次每日分析执行清理。今日、不完整录音、语音失败或健康查询出错时不清理；不处理模式保留原音。Watch 处理未完成时，手机或云端确认不会提前释放手表所需的原音。清理中断可重试，迟到的同 ID 录音或结果不会复活。
- 手表「录音与健康 → 录音设置」可开启「中断后自动续录」，默认关闭。仅系统明确允许恢复时按 0／2／5 秒至多尝试三次，等待总时限 2 分钟；用户停止、取消、关闭开关或冷启动后均不会自动开启麦克风。续录使用独立文件，并显示漏录空档。
- 手动标记保存原文件秒数，双端可以定位回听。分析返回的来源要点保留 AI 转写原文摘录、录音 ID 与估计时间范围；手机每日回顾和周／月下钻、手表纪要均可查看。本机有原音时从引用前 1 秒回听；原音已清理或尚未同步时明确显示不可回听。旧纪要不会自动补造引用。详见[连续录音、标记与来源回顾](docs/连续录音标记与来源回顾.md)。
- iPhone 的录音详情和每日回顾在应用内用 MapKit 显示录音开始附近的大致范围。未记录时显示空态；手表记录的地点坐标不会附加进新生成的纪要。界面改进见[体验优化清单](docs/体验优化清单.md)。
- 手表／手机模式的「云端备份原始录音」默认关闭；云端模式自带备份授权，选择即允许将录音与地点存入私人 iCloud。云端上传确认与日报最终清理分别记录；云端保留原音，健康窗口不上传。切换存储模式只影响后续录音，已有云端录音仍继续同步。存储同步不会自动开启方舟分析。
- 心率数值和步数原始样本在内存中用于本地关联；本地持久化查询锚点、样本 UUID／时间索引、手腕运动窗口和日报结果，用于增量更新与删除补偿。这些健康资料不写入 iCloud，也不删除系统健康库中的数据。本地目录排除系统备份。
- 激动说话前 5 分钟至少 3 个非运动心率样本才建立基线。默认同时达到 110 bpm、较基线上升 25 bpm 才记录重合，阈值可调；伴随运动单独标记。录音里的发言者不一定是佩戴者，结果用于回顾，不能证明因果或诊断疾病。系统采样可能遗漏变化。
- 会议按开始时的当地日期归档，跨午夜仍读取完整会议时段的心率。健康日统计使用首次设置时保存的固定时区；同一健康日的周／月累计只计算一次，避免差旅中更换时区造成重复统计。
- 默认模型已核实支持 M4A，按最多两分钟／4 MiB 解码负载分段上传压缩音频；完整短 M4A 直接复用文件，裁剪片段编码为 AAC。未知自定义模型自动使用 WAV，也可在设置中选择格式。上传仍有 Base64 开销。
- 两端复用静音检测：仅跳过至少 8 秒、低于保守能量阈值的明确静音，边缘留半秒缓冲；不确定声音保留。分段保存原始 frame 范围，心率关联保持原始时间映射。全静音可在本地完成；静音检测可关闭。
- 日任务只恢复索引中的未完成工作，完成清理不重复写标记；录音明细分页加载，报告首页仅读取所选日期范围。健康统计无网络也可运行，新增或删除样本只更新受影响日期，保留的语音窗口允许原音清理后补算关联。
- 手机只补发尚未收到手表确认的清理通知，Watch 结果有持久化回传队列与确认。手表录音期间暂停模型处理和自动大文件队列，可选仅充电时集中传输；实际后台执行仍由系统安排。Key 保存在调用端钥匙串，Watch 按公开配置版本通过配对即时请求获取，不写入录音、云端或导出。

## 从源码运行

最低 iOS 17／watchOS 10，使用 Xcode 16 或更新版本打开 `WristJournal.xcodeproj`，无需包依赖。

为手机和手表选择同一个开发团队并配置 HealthKit。云端功能需在两个 target 开启 iCloud／CloudKit，并使用同一个私人容器。默认容器 `iCloud.io.github.shikanon.wristjournal` 必须同时出现在两端的 `Info.plist` 与 entitlements 中。`JournalAudio.pendingAnalysis`（Int64）需设为 Queryable 并部署 schema；更换 Bundle ID 时同步修改手表 companion ID、容器 ID 和签名配置。详见[存储部署步骤](docs/存储模式与本地下载.md)及[真机验收与性能方案](docs/性能省电与真机验收.md)。

官方 Key 可由管理配置 `ArkAPIKey` 提供，或在 Debug 通过环境变量 `WRIST_JOURNAL_ARK_DEFAULT` 写入。默认模型 `doubao-seed-2-1-lite-260915`，也可配置模型或接入点 ID。仓库不包含密钥。

```sh
xcodebuild -project WristJournal.xcodeproj -scheme WristJournal \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

## 真机验收 TODO（OPEN）

先拉取最新 `main`，用 Xcode 打开工程，为双端配置签名和所需能力。真机手动验收不带 `-journal-*` 仿真／预览启动参数，使用实际麦克风录音；联网分析使用自己的有效模型配置。

- [ ] **测试环境与安装**：记录代码 commit、Mac／Xcode 版本、iPhone／Watch 型号及系统版本、测试日期；双端签名安装成功，真实麦克风授权与拒绝路径均可用。
- [ ] **录音与保存**：实际录制并回放 5／30／60 分钟音频，核对时长和音质；开始／保存／中断／失败触觉与真实状态一致，重复停止不重复保存，保存失败不提示成功。
- [ ] **表冠与防误触**：表冠旋转／按下不启动或停止录音；单击、连点、短长按和移出手指不解锁；持续长按 1.5 秒仅解锁，需再次明确点击才能停止。解锁后约 5 秒无操作回锁，滚动延长时限，松手不会误点停止。
- [ ] **熄屏、常亮与导航**：开始后立即黑底锁定；放下手腕、物理熄屏、返回表盘和切换应用时检查录音连续性；抬腕／返回应用仍锁定，常亮状态不能误操作。续录开始后，即使先前正在浏览列表，也回到锁定录音页。
- [ ] **真实中断与自动续录**：分别测试电话、Siri、闹钟和蓝牙音频路由切换，并覆盖前台／后台；默认关闭时不续录。开启后仅在系统允许时恢复，前后片段可播放、关联正确且显示实际漏录空档；系统不允许时明确保留中断状态，不声称无缝录音。

- [ ] **时间点标记**：录音时在已知语句附近打标记，保存成功后有反馈；一秒内连点不重复创建。同步和重启后标记仍在，双端回听落在对应原文件位置，续录空档不造成偏移，CSV／JSON 导出保留标记。

- [ ] **健康与定位**：验证真实授权／拒绝、粗略地点、HealthKit 采样与迟到同步；缺失数据不伪造，健康更新保留原文引用和标记，关联结果不解释为诊断。
- [ ] **录音地点地图**：对同一段实际录音检查详情和日报来源的应用内地图；在线核对底图和粗略范围，离线及无地点时检查实际呈现，确认列表可滚动、VoiceOver 可读地点说明、没有外跳入口。原音清理后仍能看地图。
- [ ] **同步与 Watch 查找**：分别测试直连、断连排队、重复文件和超过首屏分页上限后的新文件入库；核对手表/iCloud 的状态与时间各自更新。Watch 最近录音按时间排序，核对转移或清理后仍可从近期列表找到记录及已有纪要。
- [ ] **分析、回听与日期**：在分析确认页核对跨午夜和出差日期、待处理段数及保留规则；模拟确认后收到新文件，核对不纳入当次清理。检查待 Watch、云备份失败的下一步提示。连续切换两场会议的引用，确认只有一条播放控制，停止或播完后消失；用跨年周和夏令时切换样本核对时间。
- [ ] **报告首页与编辑**：冷启动直达「报告」，先读当日正文，再按需打开录音来源。用一条包含多话题的实际长录音验证正文可读，想法和事实能区分；检查空档、跨月周、日期跳转和大字号。用相册添加照片和说明，验证预览、保存、取消及重启。同步同日新录音或健康数据后，编辑版继续保留。用实际方舟配置测试「用 AI 整理当日记录」的确认、生成和失败提示。
- [ ] **设置与健康空态**：切换「不处理」确认 Mac 下载入口靠前、方舟设置隐藏。分别验证未启用、未同步样本、读取错误和部分指标缺失；可重试，空样本不会被直接显示成拒绝授权。
- [ ] **CloudKit 与 Mac 下载**：验证真实账号、容器／索引、失败重试和备份确认；Mac 浏览器证书信任、iPhone 本地网络权限、鉴权下载及到期关闭正常，导出的音频和元数据完整。
- [ ] **资源、网络与续航**：验证低电量、空间临界／不足、断网、Wi-Fi 切换、后台和长时间中断；记录系统实际恢复机会、录音时长、电量消耗与发热，不能用模拟器结果推算续航。
- [ ] **无障碍与界面用例**：在真机检查 VoiceOver、大字号、减弱动态效果和实际触摸操作，确保解锁、标记、停止和回听可达；在另一台 Mac 的完整 Xcode 环境执行 `PhoneUITests`／`WatchUITests`，记录实际执行结果。
- [ ] **最终关闭**：补齐上述测试结果、设备环境和必要证据，修复并复测失败项；由你确认真机验收通过后，再 close。
