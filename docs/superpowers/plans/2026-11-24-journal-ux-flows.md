# 恩名手记：七项体验的行为走查与实施计划

依据：走查 `218db8f` 的 SwiftUI 界面、归档索引、WatchConnectivity 入库、日报清理和 HealthKit 查询。下列用户行为是基于任务的假设，没有埋点、访谈或真机可用性数据。验收看三个结果：不用猜当前状态、能找到下一步、确认前能看清原音去向。

| 任务场景 | 用户可能怎么做、哪里会卡住 | 取舍与验收 |
| --- | --- | --- |
| 录完去手机找文件 | 点同步后看录音是否出现；分页满 50 条时到新文件仍是 50 条，容易重复点或误以为失败。若消息发送失败后转后台队列，也不应继续说请求已发。 | 同步卡折叠时仍显示当前状态；展开看 Watch 最近一次实际入库时间与独立的 iCloud 进度。以原音入库事件更新，不以列表长度或纪要、健康回传推断；等待时给出打开两端 App 的提示。 |
| 抬腕看刚结束的录音 | 先找最近录音，可能想直接看纪要；在小屏上滑过多个设置后才看到文件。 | 最近录音置顶，已生成纪要跟在对应录音的详情里。标实际来源与可回听状态；健康和偏好放在独立入口，可找回所有设置。 |
| 找纪要中某一句的依据 | 先扫纪要，再查某场会议的原文，连续点两场的标记核对。多个「停止」让人看不出正听哪一段。 | 每场会议独立折叠来源，保留标记入口；共用底部播放条，标明会议、标记或引用时段。切换来源、播放结束、离开页面时核对条的状态；原音清理后文字仍可查看。 |
| 整理多日录音 | 要先知道哪些天、几段会处理，是否会删原音；失败后要知道该开手表、修设置还是等网络。 | 确认页展示此次结束的归档日期及原音段数，包括只待备份或清理的历史日；执行限定在预览清单，后到的录音留待下次。结果按待 Watch、待备份、网络或设置等分组，保留日期和下一步。 |
| 改存储或导出 | 打开设置通常先找录音留在哪、是否经模型处理、何时清理。选择不处理后可能就是为了在 Mac 自行整理。 | 存储、处理、保留和下载优先；模型、音频格式与健康阈值放进阶。选不处理时，Mac 下载行紧接处理选项，入口仍遵循原有授权与到期流程。 |
| 出差后按日期找回顾 | 记住的是录制地的周几与几点，不熟悉 ISO 周号；移动到另一时区后，显示成手机时间会和归档日期相矛盾。 | 周回顾显示周一到周日的日期范围（可跨年）；录音用实际录制时区偏移，按该时刻计算夏令时，无时区的旧录音注明回退。日报沿用持久化的归档时区，技术标识可在详情和导出核对。 |
| 健康页看不到数据 | 不确定是否还没启用、Watch 数据没到，或读取出了问题；空的日报可能看起来像正常报告。 | 空态给出开启和刷新入口；零样本说明可从健康 App 检查数据来源和设备同步，不推断拒绝授权；查询失败提供重试。有数据但选中指标无样本时说明原因和下一步。 |

会议地点继续用 App 内 MapKit 预览；列表保持可自然滚动，也不再有外跳入口。地图加载与真实设备手势留到真机验收。

实施顺序：先改入库状态与 Watch 导航，再做来源回听和分析前后反馈，最后调整设置、日期与健康。沿用现有归档、播放和分析执行器，保留备份成功才清理的约束。用现有核心与模拟回归验证数据行为，更新界面断言，并把配对同步、地图底图、实际触摸与 HealthKit 授权留在 README 的开放清单。
