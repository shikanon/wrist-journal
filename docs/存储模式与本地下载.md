# 三种存储模式与 Mac 下载

## 用户设置

| 模式 | 原音路径 | 手表何时释放原音 |
| --- | --- | --- |
| 优先手表（默认） | 手表安全落盘 → 手机定期请求已结束日期 → 手机分析 | 日报和要求的备份完成后，手机下发清理并等待手表确认 |
| 优先手机 | 手表安全落盘 → 默认 60 分钟批量发送，可设 15–360 分钟 | 手机完整复制并原子入库的回执到达后 |
| 优先云端 | 手表安全落盘 → 私人 CloudKit → 手机查询待分析记录并下载 | CloudKit 保存操作确认成功后 |

第一批手机传输可在具备条件时开始，后续批次按间隔发送。手表录音中暂停自动大文件传输，可开启仅充电传输；手机不可用或网络失败时保留手表原音。系统后台机会不保证准点；打开 App 或连接事件可继续，手机也提供手动同步。

新安装与旧 `automatic` 偏好默认 Watch；已有明确的 Watch／Phone 偏好保留。每段录音保存创建时的目标，切换设置影响后续录音，已有云端来源仍会同步。录音全部先可靠落盘，不提供断连时可能丢失数据的无落盘模式。

选择云端模式即允许备份原音与位置；这不包含向火山方舟发送语音的授权。自动分析仍需单独开启，手动分析仍走原有确认。Watch／Phone 模式可独立选择云备份。

## Apple 平台边界

普通 watchOS App 不支持通用 `NWListener`、底层 TCP 服务或可靠的 `NWPathMonitor` 网络探测；模拟器不能反映这项限制。因此 Mac 网页下载由 iPhone 提供临时中转，不能让 Mac 直接打开手表服务。

CloudKit 是 watchOS 支持的网络方式。上传配置 `allowsCellularAccess = false`；系统仍决定使用配对手机代理、Wi-Fi 等路径，无法要求必须使用手表自身的 Wi-Fi。离开手机后的直接上传依赖已知 Wi-Fi、CloudKit 账号、系统资源和后台机会。应用不会开启虚构训练或播放静音来绕过平台限制。

依据（2026-11-22 查阅）：

- [TN3135：Low-level networking on watchOS](https://developer.apple.com/documentation/technotes/tn3135-low-level-networking-on-watchos)
- [Keeping your watchOS app’s content up to date](https://developer.apple.com/documentation/watchos-apps/keeping-your-watchos-app-s-content-up-to-date)

## 状态与恢复

- `cloudUploadedAt` 表示 CloudKit 保存已确认；`localEvictedAt` 表示本机原音已转交接收端。两者不替代 `rawDeletedAt`，后者是日报最终清理／用户删除的持久标记。
- 释放操作先写待处理意图与确认元数据，再 unlink 原音。重启只完成已提交的释放，未确认的原音继续保留。
- 手机从云端导入时清除本机释放状态，保留云确认信息。已在手机持久化的原音不重复下载；迟到的 Watch 元数据不会清除云确认。
- 最终清理前持久化云端完成通知。手机成功回写 `pendingAnalysis = 0` 后移除通知；中断可重试，已清理 UUID 不会重新导入原音。
- 手机优先的手表副本确认释放后移出手表待处理索引。清理回执与云端通知保存进度，日常连接只补发未确认变化。
- Watch 云上传和 Phone 云同步保存 1／5／15／60／180／360 分钟退避。应用关闭不会抹掉冷却；实际重试依赖下一次执行机会。
- 私人云备份只包含音频与非健康录音元数据，明确移除 `motionWindows`；HealthKit 原始样本和健康日报仍在本地。

## CloudKit 部署

1. 两个 App target 使用相同开发团队、各自正确的 Bundle ID 和同一个 iCloud／CloudKit 容器。
2. 同时设置 `Phone/Info.plist`、`Watch/Info.plist` 的 `JournalCloudContainer`，以及两端 `WristJournal.entitlements` 的容器列表。
3. 开发数据库创建 `JournalAudio`：`audio` 为 Asset，`metadata` 为 Bytes，`pendingAnalysis` 为 Int64。记录名仍为 `audio-<UUID>`。
4. 为 `pendingAnalysis` 添加 **Queryable** 索引。Watch 云来源上传时写 1，Phone 完成后写 0；普通手机备份写 0。查询仅取待处理元数据，按游标分页，再下载缺少的资产。
5. 两端登录可用的 iCloud 账号后验证保存、查询、下载与完成回写。未登录、容器未授权或缺索引会显示失败并保留来源端原音。
6. 正式发布前将 schema／索引部署到 Production。不要使用不属于当前团队的容器。

云端已完成的音频作为私人备份保留。此版本不提供云备份浏览、云端删除或 Mac 从云端直接下载的入口。Mac 下载只列出手机当前实际持有的原音；已完成日报并清理的原音不在列表中。

## Mac 临时下载

1. iPhone 和 Mac 连接同一 Wi-Fi，手机设置打开「Mac 临时下载」，先同步需要的录音。
2. 开启安全下载，将完整 `https://手机IPv4:临时端口/#会话凭证` 网址交给自己的 Mac。
3. 浏览器会提示证书由本机签发。查看证书详情，核对手机显示的 SHA-256 指纹，仅为当前连接允许访问；每次启动都会换证书和凭证。
4. 页面读取列表，点击「下载」。下载不触发清理，最终清理仍由日报流程决定。
5. 默认 10 分钟无有效操作关闭，可设 1–60 分钟。更改超时在下次启动生效。手机进入后台、Wi-Fi 地址变化／断开、手动停止也会关闭。下载中断后需重新开启并完整重下，暂不支持 Range 续传。

服务仅监听手机 Wi-Fi IPv4，TLS 至少 1.2，使用内存中的临时 RSA 身份；不写私钥。32 字节随机访问凭证放在 URL fragment，页面读取后从地址栏移除，API 使用 Bearer。列表／票据需鉴权，下载票据绑定单个录音、30 秒有效且只能消费一次。Host 必须匹配，最多 8 个连接，请求头最多 16 KiB；文件按 64 KiB 块发送。无效请求、普通页面访问和后台轮询不续期；有效操作与文件发送进展才延长单调时钟租约。

浏览器证书信任界面因 macOS／浏览器版本而异，真实手机本地网络权限和 Mac 首次信任步骤尚需真机验收。

## 验证覆盖

84 项纯 Swift 回归包含旧偏好迁移、模式决策、批量期限、录音期间暂停、确认前保留、释放重启恢复、待处理索引、重复导入保护、Host／Bearer 解析和超时边界。

新增 iOS 模拟场景使用真实 CloudBackup 调用流程与 Debug 本地传输 fixture，验证上传失败保留、成功后释放、导入幂等、健康字段排除、迟到云会议合并已清理日期及手机 ACK 释放。CloudKit 真实服务的账号、权限、索引、冲突／分页仍需真机账号验证。

HTTPS 验证使用真实 Network.framework TLS listener 和 Python 客户端：信任指定测试证书并校验 IP，不跳过 TLS 验证；无证书信任时失败、无效凭证 401、错误 Host 400、路径越界拒绝、票据重放 403、196,731 字节下载 SHA-256 一致、有效操作延长租约、无效请求不延长及到期关闭。测试使用 loopback 与 8 秒租约；正式代码只开放 Wi-Fi 和 1–60 分钟设置。

记录见 [`validation/storage-and-https.json`](validation/storage-and-https.json)。模拟验证不代表 Watch 真机网络路径、续航和 Mac 浏览器首次信任流程已经验收。
