# 连续录音、标记与来源回顾

2026-11-23。三项均已实现；保留 Watch 先录音、低交互、按需查看的操作方式。

## 使用入口与体验取舍

| 功能 | 入口 | 行为 |
| --- | --- | --- |
| 自动续录 | Watch → 录音与健康 → 录音体验 → 中断后自动续录 | 默认关闭；等待时明确显示“当前未录音”，可随时取消 |
| 时间点标记 | 录音中长按解锁 → 标记此刻 | 以录音器文件时间记录，保存成功后轻触反馈；一秒内重复点击合并 |
| 查看来源 | iPhone 录音详情／每日回顾／周月回顾下钻；Watch 纪要与来源 | 要点、转写原文摘录、录音时间范围与回听入口 |
| 保留原音 | iPhone 设置 → 每日分析与存储 → 日报后保留原音 | 默认沿用清理策略；开启后不执行日报原音清理，可持续回听 |

数码表冠继续用于系统导航，不承担标记或停止。标记位于解锁面板，避免在黑底锁定界面增加误触入口。新增文件开始时重新进入录音锁定页。

## 续录规则

中断先校验并保存可播放部分，再等待 `AVAudioSession` 的结束通知及 `shouldResume`。允许恢复后，按 0／2／5 秒延迟至多尝试三次；从中断保存起最多等待两分钟。关闭设置、手动停止、取消等待、删除待续录片段或系统拒绝恢复，均清除续录意图。重复结束通知不创建并发录音器。

续录意图仅保存在内存。重启 App 会恢复未完成文件和中断提示，将过期的“等待续录”改为手动开始提示，不会自动请求或启用麦克风。等待期间禁止播放抢占音频会话，续录开始后回到锁定录音页。没有使用假运动会话保活。实际后台执行机会由 watchOS 决定，不能承诺每类中断均自动恢复。

每段音频独立保存。`continuation` 记录会话 ID、前一段 UUID、中断时间、续录时间；详情明确显示中间未录制的时长。时间点标记始终属于所在文件，不跨空档平移。手机可从续录详情进入前一段。

## 来源与数据保留

分段分析要求模型返回逐字转写摘录及其相对时段，并让关键要点通过数组索引引用原文。解析器只复制有效索引指向的原文，拒绝空白、倒序、负数、超出分段的时段和不存在的索引，不把纪要改写当作原话。

保存时加回音频分段的原始帧偏移，因此跳过长静音后仍指向原文件中的位置。模型提供的转写和时间可能有误，界面标注“AI 识别”“约”，回听从引用前一秒开始。这里提供的是带来源的要点卡片，不保证综合纪要的每个句子均有引文，也不宣称完成独立语音真实性校验。

来源、手动标记和续录空档随 Watch 处理结果传入手机，并在日报、周／月下钻、健康数据重新关联及 JSON 导出中保留。CSV 包含标记、会话、前段和空档秒数。分享纪要或单条来源包含原文、录音 UUID 和时间范围。

默认继续沿用日报成功后清理原音的策略。开启“日报后保留原音”后，已归档音频继续保留，占用存储；再次关闭时，下次每日分析清理符合条件的文件。已清理文件不会恢复，云端备份也不会自动下载。只有本机存在可播放原音时，回听按钮才可用。

历史录音、分析任务和日报缺少新增字段时仍可解码。历史纪要不会伪造原文；有原音的用户可以重新分析获得来源。

## 验证

- 独立 Swift 检查：103 项现有核心／存储／处理检查、24 项录音体验检查、37 项新增连续性与来源检查。
- 新增检查覆盖恢复开关、系统拒绝、取消、截止时间、有限重试、旧数据解码、标记重复点击、静音偏移、错误引用索引、跨设备 Codable、保留设置、清理及重启后来源保留。
- Watch 原生应用：实际 `AVAudioFile` 编码夹具，经过中断通知观察器、恢复任务、分段保存、标记持久化和冷启动路径。不是麦克风实录。
- Watch→Phone 处理：实际音频分段、请求构造和结果文件序列化；模型回答为 Debug fixture，脚本交付结果文件，不代表真实模型识别质量或配对 WatchConnectivity 传输验收。
- XCTest 测试包可编译；当前 CoreSimulator 与 Xcode 私有框架版本不匹配，未把 XCTest 手势用例记为已执行。

实际输出及渲染记录在 [validation](validation/README.md)。真机仍需覆盖：电话、Siri、闹钟、蓝牙路由切换、长时间后台中断、低电量、空间不足、点击与 VoiceOver、触觉、持续录音耗电，以及真实配对结果传输。
