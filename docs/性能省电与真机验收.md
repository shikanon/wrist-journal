# 性能、省电实现与真机验收

## 已实现的策略

| 环节 | 实现 | 性能／省电作用 |
| --- | --- | --- |
| 录音 | 16 kHz、32 kbps 单声道 AAC，直接写文件，不实时测音量 | 限制编码、内存与存储开销；理论音频负载约 14.4 MB/小时 |
| 定位 | 每次会议开始的一次百米级定位，最多 15 秒；停止或关闭设置立即取消 | 避免持续 GPS 和会议间残留定位任务 |
| 手表存储 | 自动模式优先交手机，入库回执后释放暂存；离线保留 | 降低手表长期占用，传输失败不会先删原音 |
| 语音分析 | 只在手机串行处理；每段最多两分钟或 4 MiB PCM 负载；保存检查点 | 限制单次转换及请求体规模，避免重传已完成分段 |
| 健康日统计 | 五种指标用 HealthKit 统计查询；手表近七日报告用统计集合 | 不把整周心率原始样本搬入应用再分组 |
| 健康关联 | 只查询会议及前五分钟心率、步数和重合运动；原始样本在内存中使用 | 有界读取，不增开运动会话来提高采样频率 |
| 自动调度 | 用户开启；默认仅充电，低电量或 serious/critical 热状态暂停；后台处理到期取消，前台补跑 | 把重任务交给充电与系统合适时机；进入后台取消前台自动任务 |
| 周／月 | 从日报汇总，固定健康统计时区并去重 | 不重复语音请求或读取整月原始数据 |
| 播放界面 | 仅播放时每 500 ms 更新进度，停止即取消任务 | 移除闲置详情页的常驻定时器 |
| 清理 | 日报原子落盘，云备份确认后再清理；标记先于音频删除；跨设备通知可排队并补偿 | 限制原音增长，重启恢复删除，重复文件不复活；通知分批并去重 |

32 kbps AAC 的 14.4 MB/小时是码率计算值，不含容器开销，不是实测续航结论。PCM 的 4 MiB 是单段负载上限，不是应用总内存上限，转换缓冲、Base64 和请求体还占内存。

## 数据完成与失败

处理链为：分段语音与检查点 → 本地心率／运动关联 → 原子写日报 → 可选私人云备份原音／位置 → 写清理标记 → 删除原音 → 收缩分段笔记 → 排队通知手表。

只有结束日期和完整的可用会议才能进入清理。语音失败、健康查询实际报错、日报写入失败、备份失败均保留原音。HealthKit 空结果可能代表未授权、尚未同步或没有采样，不能区分为零心率；日报会注明缺数据，不生成关联结论。已清理音频的缺失关联无法凭空补算，分析前应先完成设备同步。

云备份默认关闭。开启时使用固定 `audio-<UUID>` 的 CloudKit 私有记录，确认成功才清理。已成功的固定记录用于重试去重。关闭后不会继续提交尚未完成的云备份；这部分原音保留，用户可重新开启重试或手动删除。健康样本、运动原始窗口和健康日报不上传 iCloud；系统健康库仍按系统规则保管数据。

对差旅录音保留开始时的时区、日期、坐标、获取时间及有效精度；跨午夜会议仍关联完整录制时段。健康统计采用固定时区，使周／月累计不因同一天多地会议而重复计算。旧录音未存时区时只能按导入设备当前时区解释，无法恢复历史发生地时区。

语音的激动线索只描述可听见的语速、音量、措辞。默认 5 分钟内至少 3 个非运动样本的中位数作为基线，心率同时达到绝对阈值和相对上升阈值才记录。运动重合单独显示；多发言者录音无法保证线索来自佩戴者。该实现是日后回顾，不提供实时医疗报警，也不能保证系统的稀疏采样捕捉所有变化。

| iPhone 模拟器应用内回归 | 通过 | 1 段合成会议 → 1 个心率重合事件，地点与纪要保留，原音删除，分段笔记收缩，重跑无重复，7 个健康日报可回顾；额外损坏录音保留并显示日期未完成 |

## 另一台电脑准备

1. 拉取本次提交，打开工程，在两个 App target 选择同一 Apple Developer 团队并启用 HealthKit。
2. 使用你的手机 Bundle ID，手表 ID 保持其 `.watchkitapp` 后缀，并修改手表 `WKCompanionAppBundleIdentifier`。
3. 如果验收云备份，在手机 Signing & Capabilities 添加 iCloud／CloudKit，注册自己的容器；同时修改 `Phone/WristJournal.entitlements` 的容器列表与 `Phone/Info.plist` 的 `JournalCloudContainer`。开发阶段使用 Development 数据库；先成功保存一条 `JournalAudio`（`audio` Asset、`metadata` Bytes）记录形成开发 schema，再在正式发布前部署 schema 到 Production。不要使用不属于当前团队的容器。
4. 手机登录 iCloud，设备安装 App。配置可用的方舟 Key 与支持音频输入的模型／接入点；授权麦克风、粗略定位和只读健康数据。备份关闭时无需成功连接 CloudKit。
5. Xcode Components 安装匹配的 iOS／watchOS 运行时。先运行核心回归，再运行两个 XCTest UI scheme；手表界面用例先拒绝麦克风权限。

## 真机验收顺序

1. **录音／中断**：各录制 5、30、60 分钟；期间熄屏、返回表盘、切 App。确认完整时长与回放，触发音频中断后保留可播放部分；强制退出／掉电的损坏文件不得进入日清理。
2. **地点**：在两个不同地点分别开始会议，确认详情、日报和地图对应各自坐标与时区；禁止定位、信号弱、录音迅速结束、关闭定位设置时，后续会议仍能重新发起定位。用 Instruments 验证请求最长约 15 秒且不会常驻。
3. **离线传输**：手机不可达时录音，确认手表原音保留；恢复后确认手机入库才删除手表暂存。选择保留手表副本，完成日报后关闭手表再打开，确认排队清理与同步补偿；重复发送已清理 UUID 不恢复手机原音。
4. **健康／语音**：先同步 HealthKit，核对五项日统计和录音完整时段心率。正常说话、运动重合、缺基线、无心率／无语音线索分别检查；用已知时间标注的合成音频检查分段时间偏移和模型 JSON。不为验收主动制造危险生理状态。
5. **失败与重启**：中断网络、使用无效模型／Key、取消后台任务，确认分段检查点与原音保留。成功日报后重启，确认摘要仍在而原音不再可播放／导出；周／月汇总无新增语音请求。
6. **云备份**：先关闭确认无 CloudKit 上传；开启后确认私有记录中音频与位置元数据存在、可读取，且不包含 HealthKit 字段。断网／退出 iCloud 时保留原音；恢复网络重试同 UUID 不重复生成记录，成功后清理本地。
7. **自动调度**：开启自动分析，分别在未充电、充电、低电量模式下检查前台补跑；用 Xcode 的 BGTask 调试触发与到期取消验证后台行为。系统不保证午夜准点运行；热状态变化必须暂停自动分析。
8. **存储／续航测量**：同一手表、相同亮度／无线条件，分别记录空闲、仅录音、录音+地点的 60 分钟电量起止、CPU 时间、定位活动和文件增长；至少重复三次取中位数。手机记录 30／120 分钟音频的分析耗时、峰值内存、重试上传次数及清理前后磁盘占用。验收后填实际数值，不能把模拟器结果换算为省电百分比。
