# 性能、省电实现与真机验收

## 已实现的策略

| 环节 | 实现 | 性能／省电作用 |
| --- | --- | --- |
| 录音 | 16 kHz、32 kbps 单声道 AAC，直接写文件，不实时测音量 | 限制编码、内存与存储开销；理论音频负载约 14.4 MB/小时 |
| 定位 | 每次会议开始的一次百米级定位，最多 15 秒；停止或关闭设置立即取消 | 避免持续 GPS 和会议间残留定位任务 |
| 手表存储 | 默认 Watch，另有 Phone 批量与 Cloud 优先；接收端确认才释放暂存 | 用户选择省电、节省手表空间或云端保存；传输失败不会先删原音 |
| 语音分析 | 已核实模型使用 M4A/AAC；每段最多两分钟或 4 MiB 解码负载；保存分段计划与检查点 | 降低上传字节；完整短 M4A 不重复编码，旧任务保留原分段进度 |
| 静音 | 手机分窗检测，至少 8 秒且 RMS ≤ −60 dBFS、峰值 ≤ −50 dBFS 才跳过，边缘保留半秒 | 减少明确静音的请求与音频字节；保留原始 frame 坐标，不改变心率时间轴 |
| 健康日统计 | HealthKit 锚定查询新增／删除样本；固定时区，仅使受影响日期失效 | 无新增数据时复用完成结果；不依赖网络或有效 Key |
| 健康关联 | 合并相邻会议及前五分钟查询；日报保留语音窗口，迟到健康样本可重算 | 减少重复查询，清理原音后仍支持健康补同步 |
| 自动调度 | 分析单独开启，默认仅充电，低电量或 serious/critical 热状态暂停；存储同步独立调度 | 健康／分析与来源同步互不授权；后台到期取消，前台补跑 |
| 周／月 | 从日报汇总，固定健康统计时区并去重 | 不重复语音请求或读取整月原始数据 |
| 播放界面 | 仅播放时每 500 ms 更新进度，停止即取消任务 | 移除闲置详情页的常驻定时器 |
| 清理 | 日报原子落盘，云备份确认后再清理；标记先于音频删除；跨设备通知可排队并补偿 | 限制原音增长，重启恢复删除，重复文件不复活；通知分批并去重 |
| 历史与恢复 | 原子可重建目录索引、未完成录音／日报／分析索引、清理完成状态；录音每页 50 条，日报每页 31 条 | 日任务不读取所有历史正文，完成后不重复写清理标记；周月页面明确标注已加载范围 |
| 失败与联网 | 持久化 1／5／15／60／180／360 分钟冷却；401／403／缺 Key 等配置变化；默认 Wi-Fi 自动上传 | 重开 App 不重试失败请求；每次语音请求重新检查，语音和 CloudKit 请求禁止蜂窝回退 |
| 设备通信 | 手机持久化待清理 ACK 清单；手表实际删完才确认；录音中暂停文件队列，可选充电集中传输 | 普通重连仅补发未确认变化；代价是同步稍晚、暂存更久 |
| 精准采集 | 默认系统采样；可选录音期间约 10 Hz CoreMotion，5 秒窗口保留运动证据，监听新增系统心率 | 默认不增加传感器负担；精准模式增加耗电，停止／中断即结束采集 |

32 kbps AAC 的 14.4 MB/小时是码率计算值，不含容器开销，不是实测续航结论。PCM 的 4 MiB 是单段负载上限，不是应用总内存上限，转换缓冲、Base64 和请求体还占内存。

## 数据完成与失败

处理链为：健康增量失效与本地日统计 → 分段语音与检查点 → 本地心率／运动关联 → 原子写日报 → 可选私人云备份原音／位置 → 写待通知及清理标记 → 删除原音 → 收缩分段笔记 → 标记清理完成 → 通知手表并等待 ACK。

只有结束日期和完整的可用会议才能进入清理。语音失败、健康查询实际报错、日报写入失败、备份失败均保留原音。HealthKit 空结果可能代表未授权、尚未同步或没有采样，不能区分为零心率；日报会注明缺数据，不生成关联结论。新版日报保存语音时间窗口，后续健康样本可补算关联；旧版日报若没有窗口，不能凭空恢复线索。

目录索引更新前写入脏标记；异常中断后从已提交文件重建一次。旧版分析任务没有手动／自动来源标志时，交由日任务策略恢复，或由用户主动点击分析，避免绕过网络条件。健康锚点与待失效区间一起原子提交，失效日期进入日任务队列后才确认消费；样本删除按 UUID／时间索引定位，未知删除保守刷新覆盖范围。初次健康回补近七天，长时间离线每次最多补 31 天；后续只检查锚点变化。索引含历史轻量描述，分页仍需排序描述，但不解码所有历史正文。

健康数值不持久化为逐样本缓存；锚点、UUID／时间范围与运动窗口保存在排除系统备份的本地目录。首次锚定查询需要读取追踪起点后的已有样本，后续只读取差量。授权变化后重建锚点和健康结果。

充电传输采用前台／连接事件与系统后台刷新机会检查电源，不保证刚插上充电器就立即发送。WatchConnectivity 已交给系统的传输取消也可能存在短暂竞态，真机需验证录音启动时的实际行为。

## 音频契约与精准模式边界

2026-11-22 查阅[火山方舟官方音频理解文档](https://ark.volcengine.com/region:cn-beijing/docs/audio-understanding)（文档更新于 2026-11-19）：示例明确使用 `doubao-seed-2-1-lite-260915`，Chat API 使用 `input_audio.data` 的纯 Base64 与 `format`；列出的格式包括 MP3、WAV、AAC、M4A，Base64 单文件不超过 25 MB。代码只将该已核实的默认模型自动切到 M4A，未知自定义模型仍用 WAV；可由用户显式选择格式。未用真实账号执行远程音频请求，接口实际可用性与纪要质量仍需真机账号验证。

按 32 kbps AAC、16 kHz 单声道 16-bit WAV 计算，每小时约为 AAC 14.4 MB／Base64 19.2 MB，与 WAV 115.2 MB／Base64 153.6 MB，理论音频负载约降低 87.5%；均不含容器、协议与裁剪重编码开销，不能当作实测网络或续航数据。

[Apple 的训练会话文档](https://developer.apple.com/documentation/healthkit/running-workout-sessions)说明高频心率采样依赖 workout session，同时会影响传感器和能量统计。因此会议精准模式主动增加的是手腕运动采集，并实时监听系统写入的新心率；不会把会议记成训练，不能宣称强制提高心率频率。若要真正连续心率，需要另行设计真实训练／受支持健康会话场景，当前功能不包含该能力。

Watch／Phone 模式的可选云备份默认关闭；Cloud 模式包含原音与地点备份授权，切换仅影响后续录音。固定 `audio-<UUID>` 私有记录用于重试去重，健康样本、运动原始窗口和健康日报不上传 iCloud。云上传确认、设备副本释放和最终日清理分别持久化；已完成备份仍保留云端原音。详细设置及 `pendingAnalysis` 索引见[存储模式与本地下载](存储模式与本地下载.md)。

对差旅录音保留开始时的时区、日期、坐标、获取时间及有效精度；跨午夜会议仍关联完整录制时段。健康统计采用固定时区，使周／月累计不因同一天多地会议而重复计算。旧录音未存时区时只能按导入设备当前时区解释，无法恢复历史发生地时区。

语音的激动线索只描述可听见的语速、音量、措辞。默认 5 分钟内至少 3 个非运动样本的中位数作为基线，心率同时达到绝对阈值和相对上升阈值才记录。运动重合单独显示；多发言者录音无法保证线索来自佩戴者。该实现是日后回顾，不提供实时医疗报警，也不能保证系统的稀疏采样捕捉所有变化。

## 另一台电脑准备

1. 拉取本次提交，打开工程，在两个 App target 选择同一 Apple Developer 团队并启用 HealthKit。
2. 使用你的手机 Bundle ID，手表 ID 保持其 `.watchkitapp` 后缀，并修改手表 `WKCompanionAppBundleIdentifier`。
3. 如果验收云端功能，两个 target 的 Signing & Capabilities 都添加 iCloud／CloudKit 并使用同一容器；同时修改两端 entitlements 与 Info.plist。开发数据库 `JournalAudio` 包含 `audio` Asset、`metadata` Bytes、`pendingAnalysis` Int64，后者设置 Queryable 索引。正式发布前部署 schema／索引到 Production。不要使用不属于当前团队的容器。
4. 手机登录 iCloud，设备安装 App。配置可用的方舟 Key 与支持音频输入的模型／接入点；授权麦克风、粗略定位和只读健康数据。备份关闭时无需成功连接 CloudKit。
5. Xcode Components 安装匹配的 iOS／watchOS 运行时。先运行核心回归，再运行两个 XCTest UI scheme；2026-11-23 更新后的手表界面用例先允许麦克风权限，拒绝权限路径由应用内回归单独验证。新版交互和剩余体验检查见 [Watch 录音体验与验收](Watch录音体验与验收.md)。

## 真机验收顺序

1. **录音／中断**：各录制 5、30、60 分钟；期间熄屏、返回表盘、切 App。确认完整时长与回放，触发音频中断后保留可播放部分；强制退出／掉电的损坏文件不得进入日清理。
2. **地点**：在两个不同地点分别开始会议，确认详情、日报和地图对应各自坐标与时区；禁止定位、信号弱、录音迅速结束、关闭定位设置时，后续会议仍能重新发起定位。用 Instruments 验证请求最长约 15 秒且不会常驻。
3. **离线传输**：确认默认优先手表，不逐段主动发送；手机不可达时原音保留，手机按结束日期拉取。手机优先模式检查批量间隔、录音中暂停和仅充电条件，手机入库 ACK 后才释放手表副本。Watch 模式完成日报后关闭手表再打开，确认排队清理与补偿；重复发送已清理 UUID 不恢复原音。
4. **健康／语音**：先同步 HealthKit，核对五项日统计和录音完整时段心率。正常说话、运动重合、缺基线、无心率／无语音线索分别检查；用已知时间标注的合成音频检查分段时间偏移和模型 JSON。不为验收主动制造危险生理状态。
5. **失败与重启**：中断网络、使用无效模型／Key、取消后台任务，确认分段检查点与原音保留。成功日报后重启，确认摘要仍在而原音不再可播放／导出；周／月汇总无新增语音请求。
6. **云备份**：先关闭确认无 CloudKit 上传；开启后确认私有记录中音频与位置元数据存在、可读取，且不包含 HealthKit 字段。断网／退出 iCloud 时保留原音；恢复网络重试同 UUID 不重复生成记录，成功后清理本地。
7. **自动调度**：开启自动分析，分别在未充电、充电、低电量模式下检查前台补跑；用 Xcode 的 BGTask 调试触发与到期取消验证后台行为。系统不保证午夜准点运行；热状态变化必须暂停自动分析。
8. **存储／续航测量**：同一手表、相同亮度／无线条件，分别记录空闲、仅录音、录音+地点的 60 分钟电量起止、CPU 时间、定位活动和文件增长；至少重复三次取中位数。手机记录 30／120 分钟音频的分析耗时、峰值内存、重试上传次数及清理前后磁盘占用。验收后填实际数值，不能把模拟器结果换算为省电百分比。
9. **网络与冷却**：开启仅 Wi-Fi 自动上传，用蜂窝／断网／低数据模式分别验证语音与备份等待、健康本地统计继续。上传中切换到蜂窝，确认禁止回退；无效 Key 重启 App 不再请求，修改 Key／模型后恢复。CloudKit 上传期间取消后台任务，确认传输取消且原音保留。
10. **增量通信与健康**：确认清理 ACK 后重连不重发历史清单；录音开始时暂停文件队列，结束后恢复；仅充电传输允许延迟执行。补同步或删除已知心率／步数样本，确认只改受影响日期，已清理原音不恢复；相邻会议、跨午夜与差旅时区分别检查。
11. **压缩与静音**：使用实际账号分别分析 M4A 与 WAV，核对接口兼容、听辨质量及字节量；已核实默认模型用 M4A，未知模型默认 WAV。使用带轻声、环境噪声和长静音的标注音频，核对静音边缘及心率关联时间；关闭静音跳过后对照结果。
12. **采集模式**：确认默认系统采样没有主动 CoreMotion；精准模式只在录音期间启动运动采集，停止／中断即释放。核对运动窗口与实际动作，比较两种模式电量；心率新增取决于系统，不以连续心率作为该模式验收标准。
13. **云端优先**：手表独立连接已知 Wi-Fi 上传，确认 CloudKit 保存后手表释放原音、手机只下载未完成记录。测试无账号、缺索引、网络中断、后台到期、相同 UUID 重试；确认原音不丢失。加入迟到录音后，已清理的同一天可重新合并。系统可能经配对手机代理，不能以强制 Watch 自身 Wi-Fi 作为验收条件。
14. **Mac 临时下载**：iPhone 与 Mac 同一 Wi-Fi，先同步并开启手机中转；使用完整 HTTPS 链接、核对指纹、完成浏览器首次信任，播放下载文件。确认默认 10 分钟及 1／60 分钟配置、有效下载延长、无效访问不续期、后台／锁屏／Wi-Fi 变化／手动停止关闭；再次开启后旧链接和票据失效，下载不触发删除。Watch 不直接运行网页服务器。
