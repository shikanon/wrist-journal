# 恩名手记体验优化清单

根据当前 iPhone 与 Watch 界面和状态逻辑走查。优先改那些用户现在需要自己猜测的状态，其次再调整界面层级。建议项尚未进行真机易用性验证。

## 这一轮已改

- **会议地点**：iPhone 录音详情和每日回顾共用 MapKit 地图。已有定位精度时用范围圈表示大概区域；没有记录时显示说明。预览不占用列表拖动手势，可打开 Apple 地图查看。新生成纪要不再附加设备记录的地点坐标。
- **本机原音**：文件可用时才显示播放和 M4A 导出。原音被清理、未在本机或录音损坏时显示对应说明；回顾中的标记与引用保留时间，原音不可用时用普通文字而非播放按钮。
- **阅读顺序**：日报把会议纪要放到健康指标之前。只有健康数据的日报不再显示原音清理或备份状态。

## 下一轮建议

| 优先级 | 发现 | 建议与验收 |
| --- | --- | --- |
| P1 | **同步后还要等多久？** [录音页](../Phone/WristJournalPhone.swift)和[同步逻辑](../Phone/PhoneJournal.swift)已经区分请求已发送与等待手表，但录音列表达到分页上限后，收到新录音时条数不变，文案可能不更新。 | 汇总为一张可收起的同步状态卡，分别显示「已请求」「等待手表」「收到新录音」「云端待重试」，附最后成功时间。即使列表条数已达到上限，新文件到达也能更新提示。 |
| P1 | **Watch 查找最近录音要先滑过设置。** [录音与健康](../Watch/WristJournalWatch.swift)把录音偏好、处理信息和健康入口放在录音列表之前，纪要还按随机 UUID 排序。 | 最近录音和对应纪要优先，按录制时间排序；设置下沉到单独入口。装有多条长会议时，进入列表即可看到最近一次录音及其实际存储状态。 |
| P1 | **回顾的播放按钮分散。** [日报](../Phone/JournalReviewView.swift)共用一个播放器，但多个可回听的会段可能同时显示「停止回听」；长纪要、引文和健康关联连在一起时也不容易定位。 | 加一个显示当前录音、标记或引用时间的播放条；引文先显示数量，可按当前会议展开。回听第二段时播放条应切换标题，第一段不再显示正在播放。 |
| P1 | **开始分析前难以判断会处理什么。** [回顾页](../Phone/JournalReviewView.swift)确认框说明策略，但不显示本次涉及日期和文件数量，等待备份与等待设备也都汇在同一段反馈中。 | 确认框预览待处理日期、段数和清理范围；完成后按原因给出下一步，比如「打开手表 App」或「在 Wi-Fi 下重试」。保留原音设置不同，确认内容随之变化。 |
| P2 | **设置页难找常用开关。** [设置页](../Phone/WristJournalPhone.swift)将普通开关与模型 ID、音频格式、心率阈值放在同一级；「不处理」模式下也继续展示模型设置。 | 首页聚焦「存在哪里」「在哪处理」「是否保留原音」；模型格式和阈值放在进阶页。「不处理」模式优先给出 Mac 临时下载入口。 |
| P2 | **日期和时间信息偏技术化。** [录音详情](../Phone/WristJournalPhone.swift)和[回顾列表](../Phone/JournalReviewView.swift)直接展示时区标识；周回顾用 `YYYY-Www`。 | 周标题换为实际日期范围；录音时间明确显示录制地的 UTC 偏移，技术时区 ID 放在详情与导出。用跨午夜、旅行和夏令时样本确认显示时间与实际归档一致。 |
| P2 | **健康缺数据时缺少下一步。** [健康页](../Phone/WristJournalPhone.swift)的空态主要提示打开手表，未面向已经开启手机健康读取、但数据尚未同步的人。 | 按读取开关、等待同步和查询错误给出对应入口；避免把没有可读样本解释为用户一定拒绝了 HealthKit 权限。 |

在下一轮优先做 **同步反馈 → Watch 录音和纪要排序 → 回顾播放状态**。这三项直接减少等待、查找和回听时的猜测，也可以分开上机验证。
